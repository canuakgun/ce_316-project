IAE — Integrated Assignment Environment

Automated grading tool for student code submissions

IAE automates the compile → run → compare pipeline for student programming assignments. It extracts student ZIP archives, compiles or interprets each submission using a configurable language setup, runs it against your test cases, and produces a colour-coded report.

All project data, configurations, and reports are stored locally in a SQLite database. No internet connection is required.

Quick start

  • 1
    Create a configuration Go to Configuration → Manage Configurations. Set the compiler/interpreter path, source filename (e.g. main.c), and compile arguments. Built-in defaults for C, C++, Python 3, and Java are seeded on first launch.
  • 2
    Create a project Click ⊕ New. Enter a project name, choose a configuration, and browse to the folder containing student .zip files.
  • 3
    Add test cases Each test case defines the command-line arguments to pass and the expected stdout. At least one test case is required before running.
  • 4
    Run Select the project and click ▶ Run. IAE extracts, compiles, and runs every submission. Results stream in live as each student is processed.
  • 5
    Review & export Click any row in the results table to inspect the diff. Use File → Export CSV or Export HTML to save the report.

Configurations

A configuration describes how to compile and run submissions for one language. Open Configuration → Manage Configurations to create, edit, delete, import, or export configurations.

Compiler / interpreter pathe.g. gcc, g++, python3, java
Compile argumentsUse {SOURCE_FILE} and {OUTPUT_PATH} as placeholders
File to compilee.g. main.c, Main.java, main.py
Relative executable pathOutput binary name, e.g. output or output.exe

Enable Interpreted for languages that do not need a separate compile step (Python, Java single-file). Configurations can be exported to .iaeconfig files and shared with colleagues.

Projects

A project ties together a configuration, a submissions directory, and a set of test cases. Select a project in the sidebar to load its details and latest report.

Use ✎ Edit to update the project name, configuration, submissions directory, or test cases. Use ✕ Delete to permanently remove the project and all its reports.

Running the grading pipeline

Click ▶ Run (or press Ctrl R) to start. The pipeline runs on a background thread so the UI stays responsive.

  • 1
    ExtractAll .zip files in the submissions directory are extracted to a temporary folder.
  • 2
    CompileFor compiled languages, the source file is compiled. A non-zero exit code marks the submission COMPILE_ERROR.
  • 3
    Run & compareThe program is executed for each test case. Output is compared with the expected value. A 10-second timeout is enforced per test case.
  • 4
    ReportResults are saved to the database and displayed live in the results table.
A submission is marked SUCCESS only if every test case passes. The first failing test case stops further execution for that student.

Results & statuses

Click any row in the results table to see the diff between actual and expected output.

SUCCESS All test cases passed.
COMPILE_ERROR The compiler exited with a non-zero code. Check the Error Message column for details.
RUNTIME_ERROR The program crashed or exceeded the 10-second timeout.
WRONG_OUTPUT The program ran but its output did not match the expected output. Click the row to see the diff.
SKIPPED The ZIP filename did not contain a valid 9-digit student ID, or extraction failed. Manual review required.

Exporting reports

After a run, use File → Export CSV or File → Export HTML to save the results.

The CSV contains one row per student: studentId, status, actualOutput, errorMessage, diffText.

The HTML file is self-contained with colour-coded status cells and can be opened in any browser.

ZIP naming convention

Each student ZIP must contain exactly one 9-digit sequence in its filename, which is used as the student ID.

220201085.zip OK — student ID: 220201085
John_220201085_hw1.zip OK — student ID: 220201085
homework.zip SKIPPED — no 9-digit ID found
220201085_220201086.zip SKIPPED — two IDs found, ambiguous
